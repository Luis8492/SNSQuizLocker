# 詰将棋（tsume / tsume5 / tsume7）

詰将棋。CSS描画の将棋盤をクリックして詰手順を指す。盤上の駒は五角形の駒枠付きで、玉方の駒は枠ごと180度回転して向きで先後が分かる。持駒も同じ駒枠で描き、枚数は駒の外に漢数字で添える（「金」三。1枚なら数字なし）。駒の文字は筆書きの楷書体 Yuji Syuku（SIL OFL 1.1、`fonts/OFL.txt`）を駒の文字＋漢数字だけにサブセットした `fonts/koma.woff2`（約9KB）で描く。再生成は `scripts/gen_koma_font.py`。
**手数ごとに別プラグイン**として登録される（`tsume.js` の `VARIANTS`）:

| id | 手数 |
|---|---|
| `tsume` | 3手詰 |
| `tsume5` | 5手詰 |
| `tsume7` | 7手詰 |

ロジック・データファイルは共通で、手数と出題データだけが異なる。
1ラウンドはいずれも3問（`tsume.js` の `VARIANTS.perRound` で変更可）。

## 出題データ

- やねうら王公開の「詰将棋500万問」（著作権を主張しない旨明示）から各手数300問を
  等間隔サンプリングして `problems.js` に同梱。攻方=先手に正規化済み（手番が w の
  局面は盤を180度回転して先後入替）。実戦形の詰み局面。
- **検証**: 元データの「N-2手では詰まない」保証は、やねうら王の高速詰め判定が
  開き王手を見逃すため稀にすり抜けがある。同梱の全問を自前ソルバーで再検証している
  （N-2手では詰まず、N手で詰む）。
- 大容量の生データ（500万問）は `tmp/` に置き、git 管理外（`.gitignore`）。
  再生成は `scripts/sample_tsume.py <手数> <候補json>`（サンプリング＋正規化）→
  `scripts/gen_problems.js <出力> 3:c3.json 5:c5.json 7:c7.json`（ソルバー検証＋出力）。
- 9手詰め以降の追加も同じ手順＋ `VARIANTS` への1行追加でよい
  （ソルバーは手数一般で動くが、長手数ほど探索が重くなる点に注意）。

## ルールエンジンと簡易詰みソルバー（shogi.js）

- 詰将棋に必要な完全な将棋ルールを自前実装: 成・不成、打ち駒、二歩、
  行き所のない駒、王手放置の禁止、打ち歩詰めの禁止。
- **簡易詰みソルバー** `mateMove` は攻方の手を王手に限定した全探索
  （分岐が少なく、3〜9手程度なら瞬時）。解答データは同梱せず、ソルバーが
  (a) ユーザーの着手が残り手数内の強制詰みを保つかの採点、
  (b) 玉方の応手の自動選択、を行う。**余詰（別解の詰み筋）も正解**。
- **無駄合は手数に数えない**（詰将棋のルール準拠）。「打った合駒を攻方が王手を
  継続しつつすぐ取り返し、同じ残り手数で詰み続けられる」合駒を無駄合と判定する
  （厳密な公式定義が無い領域の実用近似。`replyLoses` / `isUselessDrop`）。
  無駄合は逃れ手とみなさず、玉方が無駄合を打った場合はその合駒も取りも
  残り手数から引かない（`tsume.js` の `freeSquare`）。

## 操作

- 王手にならない手は選べない。駒（盤上・持駒）をクリック→行き先の候補が示される。
- 成/不成は選択式。「ヒント: 次の一手」で移動元/先が点滅。
- **不正解時**: 玉方の**逃れ手を実際に盤上で指してみせる**（棋譜表記付き。例「８三玉」）。
  「指し直す」で自分の着手前に戻る。
- 正解時は詰み上がりの盤面中央に「正解」をオーバーレイ表示してフェードアウト。
- 1ラウンドは3問（`tsume.js` の `VARIANTS.perRound`）。
